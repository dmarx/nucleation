**What happened.** On pull request 594 docs-check failed on three alternative decisions. Each title began "Alternative A to [ADR-075](../../record/decisions.d/ADR-075.md)'s step 5". The repair linked the code in each body heading and not in the title, so the lint's title-matches-heading check failed. The fix was to take the code out of the titles ("Alternative A for the admission test of a synthesis").

**Why it recurred.** This is the fourth occurrence: [ARG-124](../../record/arguments.d/ARG-124.md)'s title ([POSTMORTEM-004](../../record/postmortems.d/POSTMORTEM-004.md)), [ADR-122](../../record/decisions.d/ADR-122.md)'s (the devlog entry of 04:22:08), an account's on pull request 557, and now these three. [RETRO-tmp4n9h8](../../record/retrospectives.d/RETRO-tmp4n9h8.md), filed the same hour by the same assistant, named the third. Upstream luria refuses codes in titles (dmarx/luria#403). This record's docs workflow pins luria 1.10.0, which does not; 1.11.0 is released, and its `luria new` refuses such a title with a message saying why (checked on 2026-11-21 in a scratch environment). A rule kept in memory failed again, while the filer was writing ten pull requests in a row.

**What to change.** Bump the pinned luria to 1.11.0, in `.github/workflows/docs.yml` and wherever sessions install it, so that `luria new` refuses a code in a title at the moment it is written. Until then, a filer writing a title that names a decision or a claim should write the thing, not the code ("the admission test of a synthesis", not "[ADR-075](../../record/decisions.d/ADR-075.md)'s step 5"). The bump is a tooling change, for the owner.
