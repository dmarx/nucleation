Going wrong, then right, in the pilot of LEAD-tmpn6mi2 (the temporal
dependency graph that the exchange "Alignment consequences brainstorm"
proposed and the owner asked to start; scratch/tools/record_history/).

What went right is one habit: after every full replay, the replayed present
state (which entries are live, and how many others name each in a stated
relation field) was compared with the tree at the tip, computed directly
from the files (DP-004, fire before trusting). Each wrong theory below
showed up there as a count, not as a feeling.

1. **"A date-ordered walk of every non-merge commit is a history."** It is
   not linear: a side branch's deletion, replayed after the main line's
   addition, deletes a live entry. Found out by 131 in-degree mismatches
   and 31 live entries missing once deletions dropped their edges (before
   that fix the counts had agreed by accident: deleted entries kept their
   edges).
2. **"Then take the first-parent chain."** It is linear and exact at the
   tip, and only 10 mismatches remained, but on this record the staging
   era reaches main through nightly promotion merges: a whole batch became
   one commit, and one promotion of 4,042 entries read as a single sweep.
   Found out by the sweep list. The fix kept every commit for history and
   read present state from the tip's tree.
3. **"A code names one entry."** Codes have been handed back as temporary
   codes and reused (ADR-068, ADR-069, ADR-075), so a rename chain can make
   a live code an alias of another. Found out by the last two mismatches.
   Rule: a code live at the tip is never an alias.
4. **"A deletion is a deletion."** A bot commit adds a concrete file and
   deletes its temporary-coded twin; both map to one code, and replaying
   them in order recorded a creation and then a deletion, so 53 entries
   had two creations (the lead's check 3). Rule: an entry is deleted in a
   commit only if every change to it is a deletion. Seven remain: entries
   deleted in one commit and restored through a merge, which a walk of
   non-merge commits cannot see (the caveat LEAD-tmpn6mi2 anticipates).

After the four fixes the replay agrees with the tree on every live entry
(11,334) and every in-degree, and LEAD-199's own analysis, rerun on this
extraction, gives CASE-307's result (matched-age ratio 1.49 against 1.47).

A fifth thing that went right: the drafter who filed the lead wrote
success checks into it (reproduce CASE-307 within its interval, edge
counts within 2 %), so "done" had a definition before the code existed.
