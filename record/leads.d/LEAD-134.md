# LEAD-134: Run the imagined owner: a case with cause and report recorded apart, in which a unified self-model misdescribes who controls what

## What it would do

Build [CASE-114](../cases.d/CASE-114.md)'s simulation, with distributed control and a centralized
self-model whose reports are logged apart from the causes.

Where the record names it:

- [CLAIM-355](../claims.d/CLAIM-355.md): "Drayson's objection is still answered only conditionally"

## What would count

Reports that misattribute control in a predictable way answer Drayson's
objection to [CLAIM-355](../claims.d/CLAIM-355.md) unconditionally for the model.

## Note of 2026-11-22: carried out

Built and run ([CASE-tmpdv5tm](../cases.d/CASE-tmpdv5tm.md), an executed study variant_of
[CASE-114](../cases.d/CASE-114.md); finding [CLAIM-tmppxyo3](../claims.d/CLAIM-tmppxyo3.md); code under
scratch/studies/lead-134/). A distributed-control plant was given an accurate
and a centralized self-model, matched in parameter count and both reconstructing
the aggregate outcome exactly, so the divergence is wrong-about-control, not
merely-coarser (the case's main threat). The centralized self-model named the
wrong component as the cause of an error about four times in five (at chance),
spread blame toward the owner's global command, and governed worse after errors.
That is the predictable misattribution "What would count" asks for. The limit
holds: the modeller writes both self-models ([CLAIM-288](../claims.d/CLAIM-288.md)), so this shows what
the centralized content does once present, not that a distributed agent would
adopt it, and it bears on control, not on phenomenal properties. Whether this
answers Drayson unconditionally enough to promote [CLAIM-355](../claims.d/CLAIM-355.md), and whether to
mark this lead Done, are the owner's calls; the status and stage are left
unchanged.
