---
title: 'An optional prose field cannot be declared in luria.yaml'
created: '2026-11-25T17:29:50'
tags:
- retro
---

Going wrong, and how it was found out: the first commit of [ADR-148](../../record/decisions.d/ADR-148.md)
declared `statement:` on six schemes with only a blurb. Luria 1.11
refuses that. A field table needs a constraint (a vocabulary, `required`,
`many`, `unique`, `required_when` and the like), and an optional prose
field has none. Any `luria` command then fails while loading the config.
The owner saw it in a traceback. The declarations were withdrawn, and
`statement:` is an undeclared key, as `summary:` is.

The check that would have caught it costs a second:
`python3 -c "import luria.config as c; c.load()"`. Run it after any edit
to `luria.yaml`, even under the rule against running lint before pushing
([ADR-054](../../record/decisions.d/ADR-054.md)).
