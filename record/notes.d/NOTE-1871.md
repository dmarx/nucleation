# NOTE-1871: Zhang et al. — Hyperagents

## Contribution

A self-referential agent architecture in which the improvement mechanism is editable, and a
matched-start metric (imp@k) separating a better improver from a better product.

## Key results

1. Editable improver (abstract): "the meta-level modification procedure is itself editable, enabling metacognitive self-modification".
2. Metric (§5.2): imp@k "measures how effectively a meta agent can produce improved variants within a limited number of iterations"; to isolate the improver "we hold the meta agent fixed throughout the process".
3. Transfer (abstract): meta-level improvements "transfer across domains and accumulate across runs"; on math grading, transfer hyperagents reach imp@50 = 0.630 (CI 0.540–0.630) vs 0.0 for the initial agent (§5.2, Fig. 3).
4. Component ablation (§5.2): transferring only the meta agent gives imp@50 0.620; only the task agent 0.100.
5. Scope (§1): the results "do not yet establish unbounded or self-accelerating improvement".
6. Fixed boundary (§7): hyperagents "cannot alter the outer process that determines which agents are selected or how they are evaluated".
7. Appendix A.5: "The evaluator, task data, the underlying FM, the outer iteration budget, and the parent selection mechanism (except in Appendix E.5) lie outside this editable boundary and remain fixed to ensure safety, prevent evaluation gaming, and keep runs comparable".
8. Safety (§6): test tasks are hidden from the agents, which "prevents direct test leakage but does not eliminate gaming of the training proxy".

## Assumptions

Fixed task distributions, frozen closed foundation models, fixed evaluation protocols and (in the
main experiments) fixed parent selection; improvement measured by benchmark score.

## Concepts

Hyperagent; task agent / meta agent; metacognitive self-modification; DGM archive of stepping
stones; open-ended exploration; imp@k; editable boundary.

## Bearing on the record

[QUESTION-457](../questions.d/QUESTION-457.md) lists it among "prior art on self-improving agents", unread. **Accurate**, and
understated: imp@k with a fixed starting task agent and a matched iteration budget *is* the test
the question attributes to [LIT-2273](../literature.d/LIT-2273.md), "earlier and later improvers from identical starting
artifacts under matched budgets". This paper is a positive instance of that test in four domains.

- **[QUESTION-457](../questions.d/QUESTION-457.md)** (can a record-keeping collective become a better improver without losing
  correctability?): **bears directly on the "better improver" half**: it reports a later improver
  beating an earlier one from the same start at the same budget, for a single agent lineage, not
  a collective, and with nothing kept like the record. It **leaves open** the correctability half:
  the evaluator and selection are outside the editable boundary by design, so damage to them is
  never tested.
- **[CASE-255](../cases.d/CASE-255.md)** (improver transplant and apparatus damage): **supports** the transplant arm
  (the meta-agent-only transfer is that arm) and its outer evaluation boundary (A.5 states the
  same boundary and reason). Its damage arm has no counterpart in the paper.
- **[QUESTION-388](../questions.d/QUESTION-388.md)** (programmable system vs one governing its own reconfiguration) and **[CLAIM-485](../claims.d/CLAIM-485.md)**
  (endogenous governance adds revision of its own governing standards): **leaves open / qualifies**:
  DGM-H edits its improvement procedure but not its evaluation standard; in the record's terms it
  revises how it improves, not what counts as improvement.

## Limitations

Main text and selected appendices only; imp@k treats gains as linear (D.3 says so); transfer
results rest on 5 runs, one transfer hyperagent per source run, with wide CIs on the task-only
arm (0.0–0.560); fixed outer loop.
