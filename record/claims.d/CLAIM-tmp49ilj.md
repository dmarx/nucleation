# CLAIM-tmp49ilj: That held content was re-derived without its code in 20 of 48 reconstructed exchanges is a failure to find the code, which the anchoring account already allows, not evidence that addresses fail to anchor: it bears on discoverability, not on whether a found code stops re-derivation

## The claim

CASE-tmp4niuz finds 159 (reconstruction, item) units in which content
held under a code was re-derived without it, across 20 of 48
reconstructions. CLAIM-180's own "What it does not say" allows for this:
"A code must itself be remembered or found (QUESTION-038)". CLAIM-182
says the same: "Stable identity and discoverability may matter too".

In nearly every reported instance, the code was not cited. The
reconstruction's reader then names the entry that held the content:
"uncited", "A4 cited none", "already held". These are failures of
discovery. A collaborator who did not reach the code could not be
anchored by it. The one instance where the code was found and cited,
CLAIM-122's "re-derived again, this time cited", is a restatement that
came with its source attached.

On this reading the counts bear on discoverability, the condition
QUESTION-038 asks about. They show that codes alone did not make held
content discoverable to the exchanges' collaborators. They are silent on
CLAIM-182's thesis, which concerns whether content, once its code is in
hand, is built on rather than re-derived. CLAIM-tmp9w3p9 says why the
reconstructions cannot measure that.

## What it does not say

- It does not say discovery failures are harmless. A re-derivation that
  misses its code produces the drift and duplication CLAIM-177 records,
  whatever the cause.
- It does not say the record's views made codes discoverable. That is
  what the counts call into question.
