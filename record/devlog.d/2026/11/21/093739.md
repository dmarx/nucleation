**What happened.** After the owner merged the promotion pull request (582) into main, its codes were made permanent, and four open pull requests still cited the old temporary codes. The assistant merged staging into each and ran a script that replaced every temporary code with its permanent one, using each entry's `formerly:` field as the map. The script also replaced the codes inside `formerly:` itself, so [CLAIM-181](../../record/claims.d/CLAIM-181.md)'s history read `formerly: CLAIM-181`. That happened in 24 entries on one branch and a few on others. Three of the branches were pushed before the assistant noticed that the rewrite had touched many more files than it expected.

**How it was found.** Before pushing the fourth branch, the assistant read one rewritten file instead of trusting the count.

**The fix.** `git revert` of the three pushed commits, and a rewrite that skips the `formerly:` list. A check over every file each branch changes then found no stale temporary code left. No branch's history was rewritten, and nothing reached staging.

**What to keep.** The script was not needed at all. The owner asked whether luria already does this, and it does. `luria repair`, which the pull request's docs-check runs, upgrades a concretized code's old spelling wherever it appears, through `doc_refs.upgrade_legacy_spellings`, and skips `formerly:`. It does so in the pinned 1.10.0 as well as in 1.11.0. Nothing was needed after the promotion at all. Until a branch is merged, its own copy of each cited entry still carries the temporary code, so the code resolves there. After it merges, an old spelling resolves through `formerly:` with a `legacy-spellings` warning, not a lint failure. It is rewritten at the next repair, by the branch's docs-check on its next push or by docs-generate on main at the next promotion. The back-merge needs no repair step: main has just been repaired, and staging's own changes were repaired on their pull requests (the owner asked; the answer was to leave it as it is). A hand-rolled rewrite duplicated a mechanical repair CI already makes, against [ADR-054](../../record/decisions.d/ADR-054.md), and got it wrong. Before writing a script for a mechanical change to the record, check `luria --help` and `luria repair`'s list of repairs.
