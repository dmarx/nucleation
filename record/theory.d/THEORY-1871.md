# THEORY-1871: Linear attention is a fast weight programmer

## Source

Schlag, Irie & Schmidhuber (2021), [LIT-2642](../literature.d/LIT-2642.md); read in [NOTE-1988](../notes.d/NOTE-1988.md).

## The result

- **Identity** (§3): W(i) = W(i−1) + v(i) ⊗ φ(k(i)), y(i) = W(i)φ(q(i)),
  with a normaliser z(i) = z(i−1) + φ(k(i)) in the kernel case: "the core
  of linear Transformer variants are outer product-based Fast Weight
  Programmers". Exact for the unnormalised case; the paper reviews it
  from earlier work.
- **Capacity** (§4.1, §6.1.1): "there cannot be more than ddot orthogonal
  vectors", and on synthetic retrieval linear attention "begins to
  accumulate errors with 60 or more associations" at d_dot = 64, with
  larger-d_dot feature maps degrading later.
- **Delta rule** (§4.2, Eq. 24): W(i) = W(i−1) + β(i)(v(i) − v̄(i)) ⊗ φ(k(i)),
  v̄(i) = W(i−1)φ(k(i)), β(i) generated by the model. It does better than
  the sum rule on synthetic retrieval in which keys are reassigned to new
  values (§6.1.2, set within DPFP-1's capacity, "independent of the
  capacity regime" by Appendix D.2, unread), and on WikiText-103 in an
  overcapacity configuration (§6.3).

## What it does not show

- Anything about softmax attention, which it treats as the
  infinite-capacity limit, not as a fast weight programmer.
- That trained linear Transformers are capacity-limited in this way: the
  limit is argued from orthogonality and shown on toy tasks.
- What trained models store. Its memory is the context's, written in the
  forward pass and discarded after it; it says nothing of memories in
  trained weights, such as [THEORY-1030](THEORY-1030.md) reads into FFN units.
- A train-then-predict identity for the delta-rule layer ([QUESTION-159](../questions.d/QUESTION-159.md)).
  The layer's update can be read as an online gradient step, but that is
  the filer's arithmetic in [NOTE-1988](../notes.d/NOTE-1988.md), not the paper's statement.

## Note of 2026-11-26: von Oswald et al. (2023), read


A parallel, and an extension. [LIT-tmpuv16r](../literature.d/LIT-tmpuv16r.md) ([NOTE-tmpcktnn](../notes.d/NOTE-tmpcktnn.md)) calls its
mesa-layer "a locally optimal fast weight programmer". It places the delta
rule between Hebbian fast weights and exact optimization: "Unlike the
mesa-layer, which is optimal at every step, the delta rule requires
multiple steps to converge". It uses this paper's DPFP features and
normalization in its language-model runs. It offers no new test of this
account's capacity clause. No status change.
