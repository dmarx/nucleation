# NOTE-1867: Hu, Wang and McAuley — Evaluating Memory in LLM Agents via Incremental Multi-Turn Interactions

## Contribution

A unified, incremental-input benchmark covering four memory competencies,
including a new test of acting on the latest of conflicting facts.

## Key results

- §1: "memory serves as a compressed and distilled representation of past
  information", hence the incremental protocol.
- §1, Selective Forgetting: "The skill to revise, overwrite, or remove
  previously stored information when faced with contradictory evidence".
- §3.1, FactConsolidation: "Agents are prompted to prioritize later
  information in case of conflict and reason based on the final memory state."
- §4.2: "We observe that all methods fail on the multi-hop situation (with
  achieving at most 28% accuracy)."
- §4.2: RAG agents excel at accurate retrieval; long-context models "achieve
  the best performance on TTL and LRU"; RAG and commercial memory agents
  "retrieve only partial information from the past context".
- §4.3.4: o4-mini scores 80.0 on 6K multi-hop FactConsolidation but "its
  performance significantly drops to 14.0 when the context window reaches
  32K", so the task is solvable at short context.
- §5: current agents show "substantial limitations when faced with tasks
  requiring dynamic memory updates and long-range consistency."

## Assumptions

Four competencies drawn from memory and cognitive science; conflict
resolution by recency, instructed in the prompt; synthetic counterfactual
edits stand in for real updates (App. G argues for this); textual and
external-database memory only (parametric memory set aside).

## Concepts

Memory agent; incremental multi-turn input; Accurate Retrieval; Test-Time
Learning; Long-Range Understanding; Selective Forgetting; EventQA;
FactConsolidation (single-hop, multi-hop); long-context agent; RAG agent;
agentic memory agent; chunk size.

## Bearing on the record

[QUESTION-108](../questions.d/QUESTION-108.md)'s note (A20 and A27 "named agent-memory systems as
comparators", including "MemoryAgentBench") is accurate as far as it goes.
Precision: it is a benchmark, not a memory system, and its
"selective forgetting" is recency-based overwrite of contradicted facts with
multi-hop consequences, not dependency-rule propagation (that is [LIT-2281](../literature.d/LIT-2281.md)'s
Cascade).

- **[QUESTION-108](../questions.d/QUESTION-108.md)** (when a structured record beats a summary, a transcript or
  a posterior; three mechanisms: retaining more, easing retrieval, making
  operations cheap): **supports** the question's premise that the competence
  at stake is revision, not retrieval: retrieval-oriented memory does well on
  retrieval and fails on updates whose consequences span several facts, and
  even full context fails beyond short lengths. It does not test a structured
  record, so it leaves the question open; it is a usable external test for
  [CASE-091](../cases.d/CASE-091.md)'s revision arm.

- **[CLAIM-664](../claims.d/CLAIM-664.md)** (the record computes no withdrawals) and
  **[CLAIM-293](../claims.d/CLAIM-293.md)** (topology does not fix revision): FactConsolidation-MH is a
  test in which an older fact is withdrawn by a newer one and a multi-hop
  answer must change; it measures whether systems compute such withdrawals,
  which the record says it leaves to judgment. Bears as an external test, not
  as evidence for or against the claims.
- **[CASE-091](../cases.d/CASE-091.md)**: a candidate external task for its revision condition.
- No held entry uses "selective forgetting" or "knowledge update"; "MemGPT /
  Mem0" appears only in [NOTE-1091](NOTE-1091.md) (another work); "Zep" hits are other
  works. Duplicate check: arXiv id and title not held elsewhere.

## Limitations

Synthetic counterfactual updates; recency instructed, not inferred; a
limited set of memory agents for budget reasons (authors' statement); results
depend on chunk size.
