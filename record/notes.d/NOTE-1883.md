# NOTE-1883: Liu and Yadav — Introducing STATE-Bench: A benchmark for AI agent memory

## Key results

- The gap it targets: "Most memory benchmarks are just retrieval tests". Instead it measures "whether agents improve with experience on realistic enterprise tasks."
- Success criterion: "a set of deterministic state assertions that define success."
- Simulator stability: "simulator-induced variance was about 1%".
- Reliability: "Reporting pass^5, the percentage of tasks that succeed on all five runs".
- Baseline: GPT-5.1 without memory "completes fewer than half of the tasks reliably", and "in travel, only about 30% of tasks succeed across all five runs."
- Interface: "Pluggable agent interface. (Bring your own memory.)"
- The authors' hypothesis, not a result: inconsistency across runs "is precisely the failure mode memory is intended to mitigate."

## Assumptions

That procedural failures (skipped policy checks, misuse of tools) are what memory should fix. That LLM judges are adequate for procedural and user-experience scoring. That the memory system is a pluggable component outside the agent.

## Concepts

Stateful task; deterministic state assertion; user simulator; pass^k reliability; bring-your-own-memory; memory gap.

## Bearing on the record

It stands in for the benchmark's design, scope, metrics and baseline. It does **not** cover the repository's track structure (the "Agent Learning Track" the exchange describes), the task files or the submission protocol.

- **[CASE-253](../cases.d/CASE-253.md)**: **leaves open**. STATE-Bench varies only the memory system on fixed tasks. Nothing in it requires revising a schema or a procedure's representation. It could serve only as the "transfer" or downstream-utility check the exchange proposed, not as a test of governed schema adaptation.
- **[QUESTION-458](../questions.d/QUESTION-458.md)**: no bearing on the distinctiveness half; for the work-done half, possible downstream use only.
- **[CLAIM-266](../claims.d/CLAIM-266.md) / [QUESTION-271](../questions.d/QUESTION-271.md)**: the benchmark keeps the scorer (deterministic assertions) outside the agent for state tasks, but uses LLM judges for procedure and user experience. That is a mixed instance of separating evaluator from optimized system.
