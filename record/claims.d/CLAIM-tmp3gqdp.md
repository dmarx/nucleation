# CLAIM-tmp3gqdp: Intrinsic cognitive load is a task's least-peak threshold, and working memory is a peak budget

## The claim

Cognitive load theory, as the assistant knows it from Sweller and colleagues,
divides the demand on working memory into three loads:
- **intrinsic**, set by how many of the task's elements interact and must be
  held together;
- **extraneous**, set by how the task is presented;
- **germane**, the work of building schemas that make later tasks easier.

Its central constraint is that working memory holds only a few interacting
elements at once.

[CLAIM-571](CLAIM-571.md) (Active) says that reaching a configuration under a resource "that
must be held at each moment" has a threshold of its own. The threshold is the
least, over admissible paths, of the peak requirement along the path, and it
can exceed what either end requires. Read for a mind:
- **the resource** is items held in working memory;
- **a path** is an order of solution steps;
- **the threshold** is intrinsic load: the fewest elements any solution
  route must hold at its hardest step.

Working memory is then a *peak* budget. [CLAIM-567](CLAIM-567.md)'s three properties come
apart in a learner exactly as in any constrained system. A solution can be
*feasible*, since the answer exists and could be written down. It can still
fail to be *reachable*, since every route to it holds too much at some step.
And it can be reachable without being *reliably reached*.

## What it predicts

- Two presentations of a task with the same total work and different peaks
  differ in success, and the one with the lower peak does better.
- [CLAIM-580](CLAIM-580.md) (Active) carries over: an error of ε in estimating each step's
  load moves the estimated threshold by at most ε. A learner's rough sense
  of "this step is too much" can be good enough to choose routes by.

## What it does not say

That working memory is the only budget. Time is another, and [CLAIM-tmpg829x](CLAIM-tmpg829x.md)
says why both are needed.
