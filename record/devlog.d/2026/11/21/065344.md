On pull request 579 the adoption review put its verdicts to the owner as a
checklist. The owner ticked the two adopt groups and left a comment ruling
the third. The comment arrived as an event; the ticks did not, since editing
a description sends none. The assistant applied the comment, reported the
two adopt groups as undecided and asked again. The owner: "sorry for the
confusion, my checking the boxes you provided was intended as a go-ahead
signal".

**Why.** The assistant offered a checklist and then read only the channel
that notifies it. A ruling can arrive by a channel that does not notify.

**What changed.** [ADR-124](../../record/decisions.d/ADR-124.md) and the adoption-review skill now say a ticked
box is a ruling, and the pass reads the description's checklist as well as
the comments before applying anything. The same holds for any pull request
that offers the owner a checklist, such as the status review's under
[ADR-057](../../record/decisions.d/ADR-057.md).
