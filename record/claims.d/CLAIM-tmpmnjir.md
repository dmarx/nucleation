# CLAIM-tmpmnjir: Nucleation is a transfer test of luria: what it tests is whether distinctions first useful for governing software development stay useful for governing an inquiry, and where they do not, whether the framework can take in the difference without losing its generality

## The claim

A30 reads Nucleation as a test with two outcomes that would count against
luria: a distinction useful for software (a decision that persists, a
superseded choice, a change that must propagate to what depends on it) that
does no work in an inquiry, and a difference an inquiry needs that the
framework can take in only by ceasing to be general. A30 adds that "the
development of Luria is itself an inquiry into what a reusable governance
process has to preserve. The original webapp supplied one set of
requirements; Nucleation supplies a substantially different set." That is
[CLAIM-470](CLAIM-470.md)'s reading of inquiry as specification, applied to luria: each
project fixes which differences the abstraction must keep.

A30 also says the chronology "makes the publishing proposal an unexpected
consequence of the engineering work, rather than the premise the
engineering was designed to demonstrate". That is a claim about the
proposal's history, not its merit, and is left in this body.

## What it does not say

- Not that the test has been passed. [CLAIM-tmp5fv9h](CLAIM-tmp5fv9h.md) reads what luria's
  record shows so far.
- Not that the software distinctions and the inquiry's are the same
  mechanism; only that one framework is asked to hold both.
