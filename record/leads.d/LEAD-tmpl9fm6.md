# LEAD-tmpl9fm6: Test institutional architectures matched on ordinary performance against a battery of deliberate disturbances

## What it would do

A15 §X (https://chatgpt.com/share/6b07d7ae-9434-83ea-888b-9b20796f291c):

| Test | What we deliberately introduce |
|---|---|
| Paperclip test | A highly rewarded but narrowly specified objective |
| Capture test | Pressure on the independence of its evaluator |
| Dissent test | A justified objection opposed by powerful incumbents |
| Novelty test | A consequential situation outside the existing ontology |
| Dependency test | Withdrawal of an indispensable component |
| Readiness test | A rare contingency after prolonged ordinary operation |
| Succession test | Replacement of key human or AI participants |
| Constitutional test | Evidence that a governing standard is itself inadequate |
| Reflexivity test | Evidence that the governance platform is contributing to harm |

Success "would concern whether the institution recognizes the
discrepancy, whether the appropriate parties can intervene, whether a
corrective transition remains affordable, whether correction occurs
before it is too late, and whether the institution remains capable of
further correction afterward."

## Against the record

The matched-performance design is the record's separating-case method
applied to institutions: equal ordinary performance is what makes the
architectures' difference visible only under disturbance. CASE-166's
multilevel simulation is a setting in which several of these tests could
be run first; LEAD-tmpwlebp runs related comparisons on governed records.
No test is designed here beyond A's list: each needs its disturbance, its
measure and its matched pair specified before it can move past `idea`.
