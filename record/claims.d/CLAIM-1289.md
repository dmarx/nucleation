# CLAIM-1289: In Martin-Löf's type theory a set is given by how its canonical elements are formed, not by tests on candidates; a specification made of tests is there the set of elements of a base set such that a property holds, whose elements carry their proofs, or, with no base set given, a category, which is not a set; so reading a specification as a type holds for tests on a kind of thing already given, and not for tests on anything whatever

## The claim

[TERM-152](../terms.d/TERM-152.md) defines a specification as "a set of tests" whose realizations
are whatever passes them all. [CLAIM-949](CLAIM-949.md) reads it type-theoretically: "a
specification is a type". Martin-Löf's sets are not given that way. "a set
A is defined by prescribing how a canonical element of A is formed as well
as how two equal canonical elements of A are formed" (p. 8): by rules that
make its elements, not by tests that sort candidates.

Tests come in by one route. Given a set A and a property B(x) over it, "the
set of all a ∈ A such that B(a) holds" has as elements "pairs (a,b) with
b ∈ B(a)", the Σ-rules playing "the role of the comprehension axiom (or
the separation principle in ZF)" (p. 53). So a specification of tests over
a set already given is a type, and a proof-relevant one. Without a set to
draw candidates from, what is grasped by a criterion is a category: "A
category need not be a set, since we can grasp what it means to be an
object of a given category even without exhaustive rules for forming its
objects" (p. 21). The category of sets is the book's example, and it
"is not a set" (p. 22), so it cannot be quantified over.

So "a is an element of A" against "A is a set" tracks [TERM-152](../terms.d/TERM-152.md)'s
realization against specification, with the book's own words, "a program
... which meets the specification A" (p. 6), in the case where the
specification's tests are on a kind of thing already given. A
specification whose tests range over whatever might be proposed is, on
this account, a category.

## Bearing on the record

- In [CLAIM-783](CLAIM-783.md)'s model a version is a point of a fixed space, so a
  specification of an entry is a "such that" set over it, and the
  narrowing changes nothing there.
- A question whose answer space can be revised ([CLAIM-470](CLAIM-470.md)) is the case
  where the base set is not fixed in advance; that is where the narrowing
  bites, and where the universes of [ARG-255](../arguments.d/ARG-255.md) come in.
- [CLAIM-984](CLAIM-984.md) is a parallel on another axis. It asks whether the
  vocabulary of tests is closed; this claim asks whether the candidates
  are drawn from a set already given. Each marks a point where something
  must be grasped or stated rather than generated by rules.

## What it does not say

- Not that the record's specifications are categories. Most range over a
  kind of thing already given.
- Not that a category is defective; it is a different kind of thing,
  grasped and not generated.
