**What happened.** On 2026-11-21 docs-check failed on pull request 571 with
one violation: ADR-tmps83ka's `title:` and its body heading disagreed. The
title said "as ADR-068 does for filing"; the repair had linked the code in
the heading, `[ADR-068](ADR-068.md)`, and left the title bare, so the lint's
title-matches-heading check failed. The fix was to take the code out of the
title. This is the failure POSTMORTEM-004 reviewed the same night, for a
code in ARG-tmp5ahr5's title (now ARG-124), which also failed docs-check.

**Why it recurred.** The postmortem recorded the rule, no code in a title,
as something to remember. The assistant wrote three alternative decisions
in one script, and the rule was not in the script. A rule kept in memory
fails the second time a filer is busy.

**What to change.** Luria's own principle applies: a guard that keeps
catching you is a bug report about the workflow. Two upstream fixes, either
of which removes the hazard: the repair could leave a heading's codes as it
leaves the title's, or the title check could compare the two with links
stripped. Short of that, `luria new` could refuse a title containing a code.
Not filed upstream yet; for the owner's call, and for the retro.
