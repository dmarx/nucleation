  Chong, Zhang, Fan and Du (2026), EvoOntology: A Self-Evolving Ontology
  Layer for Data Agents. Data agents answering questions over heterogeneous
  tables, files and databases suffer an "agent–data gap". EvoOntology gives
  them an ontology exposed as an MCP server with three layers: a content
  layer (a typed graph of Terms, Mappings, Constraints and Evidence, with
  semantic-relation and structural-reference edges), a schema layer (the
  fields of those node families, admissible relation types and reference
  patterns), and a tool layer (browse and resolve tools plus a session
  manifest). A builder agent constructs an initial ontology from a training
  workload, committing only candidates verified by probe queries. An
  evolution agent then diagnoses failure signatures from trajectories,
  attributes each to the content, tool or schema level, proposes a typed
  single-level patch with an expected effect, and accepts it only if a
  paired evaluation on a held-out validation split improves by a threshold.
