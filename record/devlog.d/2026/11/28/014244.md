**Going right: a measured stopgap.** The site build had grown from 61 s
(2026-09-25) to over 40 minutes. luria's first timed build of its own site
(its Pages run 368) found one Quartz emitter, the per-page social-card
renderer, holding most of it. The owner turned it off here
(`site.social_cards: false`, luria 1.13.0), on this branch. These numbers come
from the two runs' full Actions logs. The API's 5,000-line log tail is all
upload listing at this size, so the full logs were needed to read Quartz's
own phase lines.

| phase | cards on: Pages run 586, `main`, luria 1.11.0, 12,829 pages | cards off: run 46066900986, this branch, luria 1.13.0, 13,211 pages |
|---|---|---|
| `luria site` (staging) | 155 s | 242 s |
| Quartz parse | 219 s | 292 s |
| Quartz emit | 1,322 s | 204 s |
| site step | 1,709 s | 754 s |
| output files | 49,450 | 37,211 |
| `github-pages` artifact | 444,174,957 B | 145,054,836 B |

The 12,239 fewer files are the cards, one per page. The cards-on log names
13,184 `og-image.webp` files and the cards-off log names none. Emit fell by
85%, and the deploy is now well under the 360–440 MB at which three deploys
timed out.

**Not a clean comparison.** The runs differ in luria version, page count
(+3%) and runner, and each is one run. The emit drop is far outside that
noise. Two other changes are not explained: staging grew 56% and parsing
33%, against 3% more pages. That could be the runner, or luria 1.12/1.13
staging more slowly. Neither run was timed, so neither can say. What is left
is roughly thirds (242 s, 292 s, 204 s), and the largest share luria itself
controls is staging.

**The next measurement.** This branch adds a `timings` input to the Pages
workflow. One manual run with it checked will split `luria site`'s 242 s by
phase (`LURIA_TIMINGS`) and give a per-emitter timeline for what Quartz still
emits.
